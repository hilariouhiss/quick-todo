# 第一部分 需求规格说明书

## 1. 项目概述

### 1.1 背景与目标

开发一个基于 [Iced](https://iced.rs) 的**桌面待办清单（Todos）应用**，定位为个人任务管理工具。核心价值：

- **时间追踪**：自动记录每个任务的创建 / 开始 / 结束时间，进行中任务实时显示耗时；
- **轻量组织**：任务可归属项目、设置优先级与截止时间，双列分组 + 归档管理；
- **数据可靠**：任务 / 项目存 SQLite 单文件、排序偏好存 settings.json，重启不丢失（开发阶段破坏性更新不兼容旧数据）；
- **本地优先**：单机应用，无网络依赖，数据只存本机。

### 1.2 目标用户与使用场景

| 用户              | 场景                                                   |
| ----------------- | ------------------------------------------------------ |
| 个人开发者 / 学生 | 记录待办事项，跟踪每项任务实际耗时（如写代码、做作业） |
| 时间管理用户      | 按项目组织任务，设置优先级与截止时间，逾期高亮提醒     |

### 1.3 术语表

| 术语               | 含义                                                                                    |
| ------------------ | --------------------------------------------------------------------------------------- |
| 任务（Todo）       | 一条待办记录，含标题、可选描述 / 优先级 / 项目归属 / 截止时间与三个时间点               |
| 项目（Project）    | 任务的可选归属容器，含名称、可选优先级 / 起止时间                                       |
| 状态（TodoStatus） | 未开始（Pending）/ 进行中（InProgress）/ 已完成（Done），**由时间字段推导**，不单独存储 |
| 双列分组           | 任务区左列=未开始、右列=进行中，各自独立滚动                                            |
| 归档               | 已完成任务不进入双列，经右下角统计胶囊「已完成 x」链接打开弹窗按完成时间降序查看        |
| 编辑模式           | 卡片默认只读；点击「编辑」后该卡片进入可编辑表单（即"当前任务"）                        |
| 综合排序           | 优先级优先、同级按截止时间排序的模式                                                    |

## 3. 功能需求

### 3.1 任务管理

**R1 添加任务**：任务添加**统一走「＋ 添加任务」弹窗**（标题栏**分体按钮**主按钮；右侧「▾」下拉展开「＋ 添加项目」，无快捷输入行）。弹窗字段：标题（必填）、描述（可选）、所属项目（可选，预选当前筛选的项目）、优先级（可选）、截止时间（可选）。提交成功后任务**插在列表最前**（同排序键下最新在前；组内整体顺序由排序偏好决定，见 R18 / R22）。标题输入自动 `trim()`，空白标题拒绝提交且弹窗保持打开、输入保留。

**R2 / R3 / R4 时间自动记录**：创建任务时自动写入 `created_at`（取自应用当前时间，不可为空）；点击「开始」写入 `started_at`，**仅未开始（Pending）任务可触发**；点击「完成」写入 `finished_at`，**仅进行中（InProgress）任务可触发**。非法状态流转（如未开始直接完成）静默拒绝，不产生任何副作用。

**R5 删除任务**：任意状态（含归档弹窗内）均可删除，删除后列表与磁盘同步更新。

**R8 任务归属项目**：每条任务可归属 **0 或 1 个**项目（`project_id`，`None` = 未归属）。归属展示为**只读文字**（卡片"项目"行，未归属显示"无项目"）；**归属只能经编辑模式修改**（下拉选择，含"无项目"解除选项）。

**R12 任务描述**：可选文本，弹窗添加与编辑模式可填写（空白描述存为空字符串 = 无描述，卡片不显示该行）；描述在卡片上以灰色小字只读展示（自动换行）。

**R13 弹窗添加任务**：模态弹窗（半透明遮罩 + 居中卡片），字段：标题（必填）/ 描述 / 所属项目（下拉，预选当前筛选项目）/ 优先级（下拉）/ 截止时间（文本输入实时校验 + 「快捷时间」下拉）。标题为空或时间格式非法时「创建」禁用（标题为空仅禁用不提示；时间格式非法额外红字提示）；校验通过后任务插最前、记录创建时间、关闭弹窗并落盘。

**R14 截止时间**：任务可带 `due_at`（`None` = 无截止）。卡片元信息展示"截止时间"行；**未完成且已逾期**的任务该行标红，其余灰色；无截止不显示该行。截止时间格式：`2026-01-31`（= 本地当天 23:59:59）或 `2026-01-31 18:30`（精确到分 / 秒），支持「快捷时间」回填（今天 / 明天 / 本周日 23:59，回填后可手动修改）。

**R15 编辑任务**：卡片默认**只读**展示全部属性（标题、描述、项目名、优先级徽章、状态、截止时间、三个时间点、耗时）。点击卡片右下角「编辑」进入该卡片的**编辑模式**（即"当前任务"，`App.todo_edit`）：标题 / 描述 / 项目 / 优先级 / 截止时间可修改，**时间字段永不直接编辑**（自动记录）。保存校验同弹窗（空白标题 / 非法时间 / 项目不存在被拒并**保持编辑模式**、输入保留）；「取消」丢弃修改；切换编辑其他卡片时未保存修改被丢弃。编辑模式用主题主色描边与普通卡片区分；「保存 / 取消」按钮位于卡片底部右下角（与「编辑」位置对称）。

### 3.2 项目与筛选

**R9 项目增删查改**：
- **创建**：标题栏分体按钮「▾」下拉菜单中的「＋ 添加项目」弹窗，名称必填（trim 后非空且不重名），可带可选优先级与起止时间；
- **查看**：项目单行栏芯片（优先级圆点 + 名称 + 任务计数，起止时间悬停 tooltip 提示）；
- **编辑**：项目栏右端「编辑」**展开全宽编辑面板**（名称 + 优先级 + 起止时间），保存校验通过后就地更新并落盘；
- **删除**：项目栏右端「删除」直接删除（选中该项目时出现），其下任务**自动解除归属**（`project_id` 置 `None`，任务本身保留）；被删项目正处于筛选 / 编辑态时同步复位。

**R10 按项目筛选**：项目单行栏点击芯片过滤任务区（两列同时过滤）；「全部」芯片恒在最前，显示全部任务。筛选是纯 UI 状态，不持久化。

**R16 项目起止时间**：项目可带可选 `started_at` / `finished_at`，弹窗添加与编辑面板均可设置；**同时设置时必须满足开始早于结束**；项目芯片悬停显示（tooltip：`01-01 ~ 01-31`，仅显示已设置的一端：`开始 01-01` / `结束 01-31`），编辑面板内可查看 / 修改。

**R17 项目添加**：两条路径——① **项目弹窗**（完整属性）：模态弹窗（与任务 / 归档弹窗**互斥**，打开一个关闭其余），字段：名称（必填）+ 优先级（可选）+ 开始 / 结束时间（可选）。校验：空白名称 / 重名 / 时间格式非法 / 开始≥结束 任一失败时「创建」禁用（空白名称仅禁用；重名 / 格式非法 / 范围错误额外红字提示），弹窗保持打开、输入保留；通过后创建项目（含起止时间与优先级，创建时间取自应用当前时间）、关弹窗、落盘。② **任务弹窗内快速新建**（**复用项目弹窗**）：点「＋ 新建」弹出与标题栏相同的新建项目弹窗（完整属性，见 ①），任务弹窗保留在底层（输入不丢）；校验规则与 ① 完全一致（重名红字提示、创建禁用、保持打开、输入保留）；创建成功后自动选中新项目（`project_id`）、焦点回落标题框；创建成功才落盘（`InsertProject`）。Esc / 遮罩 / 取消仅关闭项目弹窗，返回任务弹窗。

**R20 项目内联编辑**：项目行「编辑」原位展开表单（名称 + 优先级 + 开始 / 结束时间 + 保存 / 取消）。校验规则同弹窗，**重名校验排除自身**；失败红字提示并保持编辑态；「取消」丢弃修改退出编辑态；编辑期间项目被删除则仅退出编辑态。

### 3.3 时间与耗时

**R6 时间展示与实时耗时**：卡片元信息展示（本地时区 `%Y-%m-%d %H:%M:%S`）：
- 截止时间（逾期未完成标红，见 R14）；
- 创建时间（恒显示）；
- 已耗时（进行中：开始 → 当前时间，**每秒实时刷新**，橙色，标注"（实时）"）；
- 结束时间（未完成显示"—"）；
- 总耗时（已完成：开始 → 结束，绿色）。
耗时格式：`X 小时 Y 分 Z 秒` / `Y 分 Z 秒` / `Z 秒`。

### 3.4 分组与归档

**R18 双列分组显示**：任务区一行两列（各占半宽、**各自独立滚动**）——左列=未开始、右列=进行中；两列计数展示于**任务区统一标题行**（`未开始 (2)` … `进行中 (1)`，右上角为任务排序下拉），空组显示灰色提示；**组内按排序偏好排序**（见 R22，未设置均排最后、稳定排序）；状态变更后任务自动归位（开始 → 右列，完成 → 移出双列进归档）。全部为空时显示单一提示（区分"暂无任务，先添加一个吧" / "该项目暂无任务"）。

**R19 已完成归档**：已完成任务不进双列；界面右下角**统计胶囊**（`共 x 项 | 进行中 x | 已完成 x` 单行，其中「已完成 x」为**可点击链接**——主色粗体、悬停加深，其余段纯展示不可点）打开归档弹窗（模态），按**完成时间降序**（最近完成在前）列出紧凑行（标题 / 项目名 / 完成时间 / 总耗时 + 删除按钮），列表可滚动，**不受排序偏好影响**。

### 3.5 优先级与排序

**R21 任务优先级**：可选（无 / 低 / 中 / 高），弹窗添加与卡片编辑模式可设置；卡片头部状态徽章旁显示「高 / 中 / 低」小字徽章（**高红 / 中橙 / 低灰**），未设置不显示；随任务持久化。

**R22 任务排序**：任务区右上角排序下拉（任务区统一标题行右端，**无文字标签**，控制双列组内排序）：**优先级**（高→低，未设置最后）/ **截止日期**（升序，无截止最后）/ **综合**（优先级优先，同级按截止日期）。**偏好持久化**（随数据文件落盘，重启恢复，缺省「综合」）；切换即落盘。

**R23 项目优先级**：可选（无 / 低 / 中 / 高），弹窗添加与编辑面板可设置；项目芯片名称前显示**彩色圆点**（高红 / 中橙 / 低灰），未设置不显示；随项目持久化。

**R24 项目排序**：项目单行栏**最左侧**排序下拉（**无文字标签**）：优先级 / 截止日期（**按项目结束时间**升序）/ 综合（优先级优先，同级按结束时间）；「全部」芯片**恒在最前**；**偏好持久化**（同 R22，任务与项目排序互不影响）。

### 3.6 界面与交互

**R11 项目单行栏**：项目以**一行**展示在任务列表上方——排序下拉（行首，无文字标签）+ 项目标签 + 横向滚动芯片区 + 选中时的「编辑 / 删除」上下文按钮。芯片 = 优先级圆点（可选）+ 名称 + 计数，点击筛选（选中主色描边高亮），「全部」恒在最前；设置了起止时间的芯片悬停显示时间段 tooltip；无项目时显示灰字「暂无项目」。选中具体项目后，项目栏右端出现「编辑 / 删除」：「编辑」在项目栏下方展开**全宽编辑面板**（名称 + 优先级 + 起止时间 + 保存 / 取消，实时校验红字，重名校验排除自身）；「删除」直接删除并复位筛选 / 编辑态。编辑面板打开期间切换筛选不影响面板（编辑对象不变）；被编辑项目被删除后面板自动消失。该栏为纯 UI 展示，不持久化。

**R25 启动加载与错误提示**：启动时**异步加载**数据文件（不阻塞窗口）；文件缺失视为空数据；损坏 / 读取失败在界面顶部**红字提示**（"加载数据失败: …"）；**写盘失败**（IO 错误）同理提示，**绝不 panic**。

**R26 主题 / 语言 / 窗口**：**跟随系统主题**（浅色 / 深色自动切换，实时生效），**可手动切换**（左下角主题指示器 `Theme: Auto/Light/Dark`，**胶囊外壳**，点击循环：Auto → Light → Dark，无 tooltip；偏好持久化到 settings.json，重启恢复）；Auto 模式经 `iced::system::theme_changes` 订阅系统主题、**显式映射** Light / Dark（`.theme()` **恒返回 `Some`**——避免 iced 原生 `None` 跟随在"手动 → Auto"切换时"窗口边框先跟随系统、内容沿用旧主题"的分裂）；界面文案全中文；窗口 880×640、最小 480×360；标题「待办清单 · Quick Todo」；中文渲染依赖系统字体回退（Windows 下微软雅黑）。

**R27 键盘交互**：表单输入框回车 = 提交（任务弹窗 / 项目弹窗 / 两个编辑表单）；任一弹窗**或下拉菜单**打开时 **Esc 关闭当前弹窗 / 菜单**（与点击遮罩等效；任务弹窗内弹出的项目弹窗在顶层，Esc 先关闭它并返回任务弹窗）；弹窗打开时**自动聚焦**首个输入框（任务弹窗→标题、项目弹窗→名称、项目内联编辑→名称）；点击遮罩关闭弹窗。

### 3.7 持久化与兼容

**R7 持久化**：任务 / 项目存 **SQLite 单文件**（`quick-todo.db`，可执行文件同目录），排序偏好存**独立 settings.json**；每次数据变更**按操作增量写盘**（fire-and-forget），重启不丢。

**R25（补充）数据兼容**：开发阶段**破坏性更新不兼容旧数据**——SQLite schema 变更即破坏性更新：旧库不兼容（缺列 / 非 SQLite 文件）解析失败 UI 红字提示，不做自动迁移；settings.json 缺文件 / 缺键取默认「综合」；旧版 `todos.json` 不再读取、原地保留。

## 7. 总体架构

### 7.1 模块划分

```
src/
├── main.rs     入口：iced::application 装配（boot / update / view / subscription）
├── model.rs    数据模型：Todo、Project、TodoStatus、App 及表单状态（纯数据，无 IO）
├── update.rs   Message 枚举 + update 纯函数（状态流转、校验、副作用派发）
├── view.rs     视图：项目单行栏 + 编辑面板 + 双列任务区 + 卡片（只读 / 编辑模式）+ 三个弹窗 + 底部角落条（主题指示器 + 统计胶囊）
└── storage.rs  持久化：SQLite（quick-todo.db）+ settings.json，按 Op 增量写盘（单事务）
docs/
└── 需求与概要设计.md     本文档
```

分层职责：**model = 纯数据、update = 纯逻辑、view = 渲染、storage = IO**；新增功能先判断归属，不跨层写代码。

### 7.2 数据流（Elm 架构）

**视图产生 Message → update 更新状态 → 视图重新渲染**；一次性副作用经 `Task`、持续流经 `Subscription` 注入，状态本身保持纯数据。

```
用户操作 ──► Message ──► update(&mut App, Message) ──► Task（异步落盘 / 聚焦）
                        │
                        ▼
                    App 状态（todos / projects / 表单 / now / 偏好）
                        │
                        ▼
                    view(&App) ──► Element 树 ──► 渲染
     每秒时钟 ◄── Subscription ◄── iced 运行时
     Esc 监听（弹窗打开时） ◄── Subscription ◄── iced 运行时
```

### 7.3 核心设计原则

1. **状态由时间字段推导，不存储状态枚举**（详见 8.2）——从结构上杜绝脏数据；
2. **update 是纯函数**：时间戳一律取自 `app.now`（每秒 Tick 刷新），不在 update 中调用 `Utc::now()`；副作用只通过返回的 `Task` 表达；
3. **时间统一 UTC 存储**，仅在 view 层用 `chrono::Local` 格式化展示；
4. **持久化 fire-and-forget**：数据变更派发 `storage::Op`（携带完整行状态），单事务执行 SQL；排序偏好整文件覆写 `settings.json`；成功静默、失败记入 `app.error`；增量写、无队列；
5. **非法状态流转静默拒绝**，不产生任何副作用；
6. **错误不崩溃**：文件缺失 = 空数据，损坏 = UI 提示；
7. **分组 / 排序是派生展示**，放 view 内部私有函数；update 层不改变列表顺序（仅插最前 / 删除 / 就地更新）。

## 8. 数据模型设计

### 8.1 领域模型

```rust
pub struct Todo {
    pub id: Uuid,                       // v7
    pub title: String,                  // trim 后非空
    pub description: String,   // 空串 = 无描述
    pub priority: Option<Priority>,   // None = 未设置
    pub project_id: Option<Uuid>,     // None = 未归属
    pub due_at: Option<DateTime<Utc>>, // None = 无截止
    pub created_at: DateTime<Utc>,      // 创建时写入，不可为空
    pub started_at: Option<DateTime<Utc>>,  // 点击"开始"时写入
    pub finished_at: Option<DateTime<Utc>>, // 点击"完成"时写入
}

pub struct Project {
    pub id: Uuid,
    pub name: String,                   // trim 后非空且不重名
    pub priority: Option<Priority>,
    pub started_at: Option<DateTime<Utc>>,
    pub finished_at: Option<DateTime<Utc>>,
    pub created_at: DateTime<Utc>,
}
```

> 模型结构**不序列化**（SQLite 列映射在 storage 层手工完成）；排序偏好与主题模式 `Settings { sort_mode, project_sort_mode, theme_mode }` 是唯一 JSON 序列化对象（settings.json，`SortMode` / `ThemeMode` 存英文变体名，缺省「综合」/「跟随系统」）。

**值类型**：

```rust
pub enum TodoStatus { Pending, InProgress, Done }   // 派生展示，不序列化
pub enum Priority { Low, Medium, High }             // 派生 Ord：低<中<高；不序列化（库存英文变体名文本）
pub enum SortMode { Priority, Due, Combined }       // #[default] = Combined；派生 Serialize/Deserialize（settings.json 存英文变体名）
```

### 8.2 状态推导（核心设计决策）

**不单独存状态枚举，由时间字段推导**：

```rust
pub fn status(&self) -> TodoStatus {
    if self.finished_at.is_some() { TodoStatus::Done }
    else if self.started_at.is_some() { TodoStatus::InProgress }
    else { TodoStatus::Pending }
}
```

时间字段是**唯一事实来源**（single source of truth），从结构上杜绝"状态枚举与时间不一致"的脏数据（如 `finished_at` 已有值但状态仍是 Pending）。**严禁为 `Todo` 增加持久化的状态字段。**

```
创建（记录 created_at，插入列表最前）
   │
   ▼
Pending ──点击"开始"──► InProgress ──点击"完成"──► Done
（未开始）              （进行中）                  （已完成，移入归档）
   ▲                        │
   └────── 任意状态均可"删除" ┘
```

耗时计算 `duration(now)`：进行中 = `now - started_at`（实时）；已完成 = `finished_at - started_at`；未开始 = `None`。

### 8.3 排序键设计

排序是**派生展示**：view 层对任务 / 项目拷贝按排序键稳定排序，update 层不改列表顺序。所有排序键统一为"可选值排最后"的元组形态，直接按元组排序：

| 排序键                        | 形态                            | 语义                           |
| ----------------------------- | ------------------------------- | ------------------------------ |
| `Todo::priority_order_key`    | `(是否未设置, Reverse<优先级>)` | 高→低，未设置最后              |
| `Todo::due_order_key`         | `(是否无截止, 截止时间)`        | 截止升序，无截止最后           |
| `Todo::combined_order_key`    | 上述两者拼接                    | 优先级优先，同级按截止         |
| `Project::end_order_key`      | `(是否无结束, 结束时间)`        | 按**结束时间**升序（项目截止） |
| `Project::combined_order_key` | 优先级 + 结束时间               | 优先级优先，同级按结束         |

### 8.4 应用状态（App）

    pub error: Option<String>,          // 加载 / 保存错误提示

**UI 状态与持久化状态的边界**（设计约定）：
- 项目筛选、三个弹窗、下拉菜单、归档开关、两个编辑表单 = **纯内存**，不参与序列化；
- 弹窗互斥的**例外**：任务弹窗内「＋ 新建」（`OpenQuickProjectDialog`）叠加打开项目弹窗——`add_dialog` 保留、关闭后返回；标题栏下拉菜单打开时，打开任一弹窗即自动收起菜单（`OpenAddDialog` / `OpenProjectDialog` / `OpenCompletedDialog` 清 `add_menu_open`）；
- 排序偏好与主题模式 = **例外**，随 Store 持久化、启动经 `Loaded` 恢复、切换即落盘。

### 8.5 表单状态（纯内存）

| 类型            | 字段                                                                               | 说明                                                                                                       |
| --------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `AddDialog`     | title / description / priority / project_id / due_input / due_parsed | 任务弹窗；`due_parsed` 缓存实时解析结果（`Err` = 格式错误提示）；快速新建项目走 `OpenQuickProjectDialog`（复用项目弹窗，无独立状态） |
| `ProjectDialog` | name / priority / start_input / start_parsed / end_input / end_parsed              | 项目弹窗；起止时间各自实时解析；可从任务弹窗「＋ 新建」叠加打开（创建成功后自动选中新项目，关闭后返回） |
| `ProjectEdit`   | project_id / name / priority / start_input / start_parsed / end_input / end_parsed | 项目内联编辑；打开时从项目字段**预填**（时间回填为可解析文本）                                             |
| `TodoEdit`      | todo_id / title / description / priority / project_id / due_input / due_parsed     | 卡片编辑模式；打开时预填全字段                                                                             |

设计要点：**输入文本与解析结果成对缓存**，输入变化即实时解析（非法格式立即红字提示），提交时复用缓存结果做最终校验——视图层与 update 层各自独立校验（view 用于禁用按钮，update 用于防御性拒绝）。

### 8.6 时间工具（model 层纯函数）

- `parse_datetime(&str) -> Result<Option<DateTime<Utc>>, String>`：空串 → `Ok(None)`；`YYYY-MM-DD HH:MM[:SS]` → 精确时刻；`YYYY-MM-DD` → 本地当天 **23:59:59**；其他 → `Err(格式提示)`。本地时区语义、存储转 UTC（DST 边界取最早映射）。
- `format_due(DateTime<Utc>) -> String`：UTC → 本地 `%Y-%m-%d %H:%M`（分钟粒度），保证 `parse_datetime(format_due(dt))` 闭环还原同一时刻。
- `QuickDue { Today, Tomorrow, Sunday }`：基于 `app.now` 计算本地日期当天 23:59 的回填文本（周日 = 本日时即今天）。
- `format_time`（view 层）：`%Y-%m-%d %H:%M:%S` 本地展示。
- `format_duration`（view 层）：`X 小时 Y 分 Z 秒` / `Y 分 Z 秒` / `Z 秒`。

## 9. 持久化设计

### 9.1 存储位置与格式

任务 / 项目存 **SQLite 单文件**（`quick-todo.db`），排序偏好存**独立 JSON**（`settings.json`）；两个文件都放在**可执行文件同目录**（`std::env::current_exe()` 父目录，失败退化当前目录；`cargo run` 时即 `target/debug/`）。

```rust
// storage.rs 中定义
pub struct Store { todos: Vec<Todo>, projects: Vec<Project>, sort_mode: SortMode, project_sort_mode: SortMode, theme_mode: ThemeMode }
// 内存结构，不序列化

pub enum Op {
    InsertTodo(Todo), UpdateTodo(Todo), DeleteTodo(Uuid),
    InsertProject(Project), UpdateProject(Project), DeleteProject(Uuid),
}
// 增量写盘操作：每个 Op 携带完整行状态，单事务执行
```

- **Schema**（`storage::SCHEMA`）：`todos` / `projects` 两张表；时间存 ISO-8601 UTC 文本（写 `to_rfc3339()`，读 `parse_from_rfc3339` + 转 UTC）；优先级存英文变体名文本（`"Low"` / `"Medium"` / `"High"`）；`todos.project_id` 外键 `REFERENCES projects(id) ON DELETE SET NULL`；索引 `todos(project_id)` / `todos(due_at)`；每个连接 `PRAGMA foreign_keys = ON`；
- **settings.json**：`{ "sort_mode": "Combined", "project_sort_mode": "Priority", "theme_mode": "System" }`（`serde_json::to_string_pretty` 整文件覆写，无读-改-写）；`theme_mode` 为**必填键**——旧文件缺键解析失败红字提示（破坏性更新不迁移），缺**文件**取默认；
- **连接**：rusqlite 同步 API 一律经 `spawn_blocking` 包裹；`busy_timeout(2s)` 防并发写撞锁；每次操作临时开连接、用后即关，不维护连接池。

### 9.2 兼容与迁移策略

开发阶段**破坏性更新不兼容旧数据**：schema 变更即破坏性更新——旧库不兼容（缺列 / 非 SQLite 文件）直接报错 UI 红字提示，不做自动迁移；settings.json 缺文件 / 缺键取默认「综合」；旧版 `todos.json` 不再读取、原地保留。

```
load():
  ├─ quick-todo.db 缺失              → 空数据（首次写入自动建表）
  ├─ 读取成功（ORDER BY rowid）      → todos + projects
  ├─ 数据库损坏 / SQL 错误           → Err  # UI 红字提示（NOTADB 在首条语句时触发）
  └─ settings.json 缺失 / 缺键       → 默认「综合」；损坏 → Err
```

### 9.3 读写策略

- **加载**：`boot` 返回 `Task::perform(storage::load(), Message::Loaded)`，不阻塞窗口启动；`Loaded(Ok)` 填充 todos / projects / 排序偏好，`Loaded(Err)` 记入 `app.error`；
- **写入（增量）**：`update` 中数据变更后调用 `persist(op)`——每个 Op 携带完整行状态，`Task::perform(storage::apply, Message::Saved)` 在**单事务**内执行对应 SQL（fire-and-forget）；排序偏好走 `persist_settings(app)` → `storage::save_settings` 整文件覆写；`Saved(Ok)` 静默，`Saved(Err)` 记入 `app.error`；
- **触发落盘的变更**：任务（添加 → `InsertTodo`；开始 / 完成 / 编辑保存 → `UpdateTodo`；删除 → `DeleteTodo`）、项目（项目弹窗创建 / **任务弹窗快速新建** → `InsertProject`；编辑保存 → `UpdateProject`；删除 → `DeleteProject` 事务内级联解除归属）、排序偏好与**主题模式**切换（写 settings.json）；
- **不触发落盘的变更**：弹窗打开 / 关闭 / 输入、筛选、项目栏 / 编辑面板（纯 UI）、编辑表单输入、Tick。

## 10. 消息与状态流转设计

| 加载保存    | `Loaded(Result<Store,String>)` / `Saved(Result<(),String>)`                                                                                                                                                                 | 失败记 `app.error`，成功静默                                     |
| 时钟 / 系统  | `Tick(DateTime<Utc>)` / `SystemThemeChanged(bool)` | 仅刷新 `app.now` / `system_dark`（不落盘） |
| 排序偏好 / 主题 | `SortModeChanged` / `ProjectSortModeChanged` / `CycleThemeMode`                                                                                                                                                           | 切换即落盘（写 settings.json）                                   |

| 项目弹窗    | `OpenProjectDialog` / `CloseProjectDialog` / `ProjectNameChanged` / `ProjectStartChanged` / `ProjectEndChanged` / `ProjectDialogPriorityChanged` / `SubmitProjectDialog`                                                    | 标题栏下拉菜单打开：收起菜单 + 互斥关其余 + 聚焦名称框；任务弹窗内打开（`OpenQuickProjectDialog`）：保留任务弹窗，创建成功后自动选中新项目 + 聚焦标题框；提交成功才落盘 |
| 项目编辑    | `StartEditProject(id)` / `ProjectEditNameChanged` / `ProjectEditStartChanged` / `ProjectEditEndChanged` / `ProjectEditPriorityChanged` / `SaveEditProject` / `CancelEditProject`                                            | 进入编辑态预填 + 聚焦名称框；保存成功才落盘                      |
| 项目 / 筛选 | `DeleteProject(id)` / `SelectProject(Option<Uuid>)`                                                                                                                                                                         | 删除落盘 + 解除归属 + 复位筛选/编辑态；筛选纯内存                |
| 卡片编辑    | `EditTodo(id)` / `CancelEditTodo` / `EditTitleChanged` / `EditDescriptionChanged` / `EditProjectChanged` / `EditPriorityChanged` / `EditDueChanged` / `EditQuickDue` / `SaveEditTodo`                                       | 预填全字段；保存成功才落盘；切换编辑目标丢弃未保存修改           |
| 界面        | `ToggleAddMenu` / `OpenCompletedDialog` / `CloseCompletedDialog`                                                                                                                                                            | 纯 UI 状态，不落盘；下拉菜单展开 / 收起，归档弹窗互斥打开        |

### 10.2 校验规则（update 层防御性校验，view 层同步禁用按钮）

| 场景         | 校验                                                                 | 失败行为                       |
| ------------ | -------------------------------------------------------------------- | ------------------------------ |
| 任务弹窗提交 | 标题 trim 非空；`due_parsed` 为 `Ok`；项目存在（`None` 或命中）      | 恢复弹窗（输入保留），无副作用 |
| 任务编辑保存 | 同上（标题 trim、时间合法、项目存在）                                | 保持编辑态（输入保留）         |
| 项目弹窗提交 | 名称 trim 非空且不重名；起止时间各自 `Ok`；同时设置时 start < finish（标题栏与任务弹窗内快速新建**共用同一校验**） | 恢复弹窗（输入保留）           |
| 项目编辑保存 | 同上，**重名校验排除自身**                                           | 保持编辑态（输入保留）         |
| 状态流转     | 仅 Pending 可开始、仅 InProgress 可完成                              | 静默拒绝                       |
| 防御性       | 弹窗 / 编辑未打开时收到输入或提交消息                                | 忽略（`Task::none()`）         |
| 防御性       | 项目 / 任务下拉选择不存在的 id                                       | 拒绝                           |

> 注：所有提交类消息在 `take()` 表单后用闭包 `restore` 恢复——保证校验失败时表单内容（含错误提示）完整保留。

### 10.3 副作用设计

- **一次性**：异步落盘（`Task::perform`）、输入框聚焦（`iced::widget::operation::focus`，返回的 Task 在下一次渲染时生效）；
- **持续流**：`Subscription::run(|| iced::stream::channel(1, ...))` 每秒推送 `Utc::now()` → `Tick`；**发送失败（应用退出）必须 break 结束流**；
- **条件订阅**：任一弹窗**或下拉菜单**打开时追加 `iced::event::listen_with` 监听 Esc → `CloseActiveDialog`（`listen_with` 只接受无捕获 fn 指针，固定发 `CloseActiveDialog`，由 update 分派到当前打开的弹窗 / 菜单）。

| model   | `#[test]` 纯逻辑                   | 时间字段与状态推导、耗时计算、排序键、UUID 唯一性、严格 schema（缺字段反序列化报错）、`parse_datetime` / `format_due` 闭环、`QuickDue` 计算、`ThemeMode`（默认 / 标签 / 循环 / 序列化）          |
| update  | `#[test]` 纯函数（固定 `app.now`） | 全部消息：状态流转合法性、弹窗 / 编辑表单各输入与校验失败保持、互斥、提交创建（时间取自 `app.now`、trim、插最前）、**快速新建项目（复用项目弹窗：叠加打开保留任务弹窗 / 创建选中 / 重名与非法保持 / Esc 与取消返回 / 端到端归属 / 归档弹窗互斥清空叠加态）**、删除复位、排序偏好、主题循环切换、系统主题跟随（`SystemThemeChanged`）、防御性 noop |
| storage | `#[tokio::test]` 临时 `.db` / `settings.json` | Op 增量写往返（插入 / 更新 / 删除 / 删除项目级联解除归属）、settings 往返（含 theme_mode）、**旧文件缺 theme_mode 键报错（不迁移）**、文件缺失空数据、损坏文件报错                                        |

### 12.2 测试约定

- 测试写在各模块内 `#[cfg(test)] mod tests`，与被测代码同文件；
- storage 测试用 `std::env::temp_dir()` + 进程 id 命名临时 `.db` / `settings.json` 文件，用后删除；
- 时间相关测试用固定时间戳（`Utc.timestamp_opt(...)`），不用 `Utc::now()` 断言；
- **任何新的 Message / 状态流转 / 持久化变更必须补对应测试**，`cargo test` 全绿是交付前提。
