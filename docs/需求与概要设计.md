# 第一部分 需求规格说明书

## 1. 项目概述

### 1.1 背景与目标

开发一个基于 [Iced](https://iced.rs) 的**桌面待办清单（Todos）应用**，定位为个人任务管理工具。核心价值：

- **时间追踪**：自动记录每个任务的创建 / 开始 / 结束时间，进行中任务实时显示耗时；
- **轻量组织**：任务可归属项目、设置优先级与截止时间，双列分组 + 归档管理；
- **数据可靠**：JSON 持久化，重启不丢失，兼容旧版数据文件；
- **本地优先**：单机应用，无网络依赖，数据只存本机。

### 1.2 目标用户与使用场景

| 用户              | 场景                                                   |
| ----------------- | ------------------------------------------------------ |
| 个人开发者 / 学生 | 记录待办事项，跟踪每项任务实际耗时（如写代码、做作业） |
| 时间管理用户      | 按项目组织任务，设置优先级与截止时间，逾期高亮提醒     |

### 1.3 术语表

| 术语               | 含义                                                                                    |
| ------------------ | --------------------------------------------------------------------------------------- |
| 任务（Todo）       | 一条待办记录，含标题、可选描述 / 优先级 / 项目归属 / 截止时间与三个时间点               |
| 项目（Project）    | 任务的可选归属容器，含名称、可选优先级 / 起止时间                                       |
| 状态（TodoStatus） | 未开始（Pending）/ 进行中（InProgress）/ 已完成（Done），**由时间字段推导**，不单独存储 |
| 双列分组           | 任务区左列=未开始、右列=进行中，各自独立滚动                                            |
| 归档               | 已完成任务不进入双列，经侧边栏「已完成 (N)」弹窗按完成时间降序查看                      |
| 编辑模式           | 卡片默认只读；点击「编辑」后该卡片进入可编辑表单（即"当前任务"）                        |
| 综合排序           | 优先级优先、同级按截止时间排序的模式                                                    |

## 3. 功能需求

### 3.1 任务管理

**R1 添加任务**：任务添加**统一走「＋ 添加任务」弹窗**（标题栏唯一入口，无快捷输入行）。弹窗字段：标题（必填）、描述（可选）、所属项目（可选，预选当前筛选的项目）、优先级（可选）、截止时间（可选）。提交成功后任务**插在列表最前**（同排序键下最新在前；组内整体顺序由排序偏好决定，见 R18 / R22）。标题输入自动 `trim()`，空白标题拒绝提交且弹窗保持打开、输入保留。

**R2 / R3 / R4 时间自动记录**：创建任务时自动写入 `created_at`（取自应用当前时间，不可为空）；点击「开始」写入 `started_at`，**仅未开始（Pending）任务可触发**；点击「完成」写入 `finished_at`，**仅进行中（InProgress）任务可触发**。非法状态流转（如未开始直接完成）静默拒绝，不产生任何副作用。

**R5 删除任务**：任意状态（含归档弹窗内）均可删除，删除后列表与磁盘同步更新。

**R8 任务归属项目**：每条任务可归属 **0 或 1 个**项目（`project_id`，`None` = 未归属）。归属展示为**只读文字**（卡片"项目"行，未归属显示"无项目"）；**归属只能经编辑模式修改**（下拉选择，含"无项目"解除选项）。

**R12 任务描述**：可选文本，弹窗添加与编辑模式可填写（空白描述存为空字符串 = 无描述，卡片不显示该行）；描述在卡片上以灰色小字只读展示（自动换行）。

**R13 弹窗添加任务**：模态弹窗（半透明遮罩 + 居中卡片），字段：标题（必填）/ 描述 / 所属项目（下拉，预选当前筛选项目）/ 优先级（下拉）/ 截止时间（文本输入实时校验 + 「快捷时间」下拉）。标题为空或时间格式非法时「创建」禁用（标题为空仅禁用不提示；时间格式非法额外红字提示）；校验通过后任务插最前、记录创建时间、关闭弹窗并落盘。

**R14 截止时间**：任务可带 `due_at`（`None` = 无截止）。卡片元信息展示"截止时间"行；**未完成且已逾期**的任务该行标红，其余灰色；无截止不显示该行。截止时间格式：`2026-01-31`（= 本地当天 23:59:59）或 `2026-01-31 18:30`（精确到分 / 秒），支持「快捷时间」回填（今天 / 明天 / 本周日 23:59，回填后可手动修改）。

**R15 编辑任务**：卡片默认**只读**展示全部属性（标题、描述、项目名、优先级徽章、状态、截止时间、三个时间点、耗时）。点击卡片右下角「编辑」进入该卡片的**编辑模式**（即"当前任务"，`App.todo_edit`）：标题 / 描述 / 项目 / 优先级 / 截止时间可修改，**时间字段永不直接编辑**（自动记录）。保存校验同弹窗（空白标题 / 非法时间 / 项目不存在被拒并**保持编辑模式**、输入保留）；「取消」丢弃修改；切换编辑其他卡片时未保存修改被丢弃。编辑模式用主题主色描边与普通卡片区分；「保存 / 取消」按钮位于卡片底部右下角（与「编辑」位置对称）。

### 3.2 项目与筛选

**R9 项目增删查改**：
- **创建**：侧边栏「＋ 添加项目」弹窗，名称必填（trim 后非空且不重名），可带可选优先级与起止时间；
- **查看**：侧边栏项目列表（名称 + 优先级圆点 + 任务计数 + 可选起止时间小字）；
- **编辑**：项目行「编辑」**原位展开内联表单**（名称 + 优先级 + 起止时间），保存校验通过后就地更新并落盘；
- **删除**：项目行「删除」直接删除，其下任务**自动解除归属**（`project_id` 置 `None`，任务本身保留）；被删项目正处于筛选 / 编辑态时同步复位。

**R10 按项目筛选**：侧边栏点击项目行过滤任务区（两列同时过滤）；「全部」行恒在项目列表最前，显示全部任务。筛选是纯 UI 状态，不持久化。

**R16 项目起止时间**：项目可带可选 `started_at` / `finished_at`，弹窗添加与内联编辑均可设置；**同时设置时必须满足开始早于结束**；侧边栏项目行名称下方小字展示（`01-01 ~ 01-31`，仅显示已设置的一端：`开始 01-01` / `结束 01-31`）。

**R17 项目弹窗添加**：模态弹窗（与任务 / 归档弹窗**互斥**，打开一个关闭其余），字段：名称（必填）+ 优先级（可选）+ 开始 / 结束时间（可选）。校验：空白名称 / 重名 / 时间格式非法 / 开始≥结束 任一失败时「创建」禁用（空白名称仅禁用；重名 / 格式非法 / 范围错误额外红字提示），弹窗保持打开、输入保留；通过后创建项目（含起止时间与优先级，创建时间取自应用当前时间）、关弹窗、落盘。

**R20 项目内联编辑**：项目行「编辑」原位展开表单（名称 + 优先级 + 开始 / 结束时间 + 保存 / 取消）。校验规则同弹窗，**重名校验排除自身**；失败红字提示并保持编辑态；「取消」丢弃修改退出编辑态；编辑期间项目被删除则仅退出编辑态。

### 3.3 时间与耗时

**R6 时间展示与实时耗时**：卡片元信息展示（本地时区 `%Y-%m-%d %H:%M:%S`）：
- 截止时间（逾期未完成标红，见 R14）；
- 创建时间（恒显示）；
- 已耗时（进行中：开始 → 当前时间，**每秒实时刷新**，橙色，标注"（实时）"）；
- 结束时间（未完成显示"—"）；
- 总耗时（已完成：开始 → 结束，绿色）。
耗时格式：`X 小时 Y 分 Z 秒` / `Y 分 Z 秒` / `Z 秒`。

### 3.4 分组与归档

**R18 双列分组显示**：任务区一行两列（各占半宽、**各自独立滚动**）——左列=未开始、右列=进行中；每组标题带计数（`未开始 (2)`），空组显示灰色提示；**组内按排序偏好排序**（见 R22，未设置均排最后、稳定排序）；状态变更后任务自动归位（开始 → 右列，完成 → 移出双列进归档）。全部为空时显示单一提示（区分"暂无任务，先添加一个吧" / "该项目暂无任务"）。

**R19 已完成归档**：已完成任务不进双列；侧边栏底部「已完成 (N)」按钮（N = 完成数）打开归档弹窗（模态），按**完成时间降序**（最近完成在前）列出紧凑行（标题 / 项目名 / 完成时间 / 总耗时 + 删除按钮），列表可滚动，**不受排序偏好影响**。

### 3.5 优先级与排序

**R21 任务优先级**：可选（无 / 低 / 中 / 高），弹窗添加与卡片编辑模式可设置；卡片头部状态徽章旁显示「高 / 中 / 低」小字徽章（**高红 / 中橙 / 低灰**），未设置不显示；随任务持久化。

**R22 任务排序**：任务区排序下拉（控制双列组内排序）：**优先级**（高→低，未设置最后）/ **截止日期**（升序，无截止最后）/ **综合**（优先级优先，同级按截止日期）。**偏好持久化**（随数据文件落盘，重启恢复，缺省「综合」）；切换即落盘。

**R23 项目优先级**：可选（无 / 低 / 中 / 高），弹窗添加与内联编辑可设置；侧边栏项目行名称前显示**彩色圆点**（高红 / 中橙 / 低灰），未设置不显示；随项目持久化。

**R24 项目排序**：侧边栏排序下拉：优先级 / 截止日期（**按项目结束时间**升序）/ 综合（优先级优先，同级按结束时间）；「全部」行**恒在最前**；**偏好持久化**（同 R22，任务与项目排序互不影响）。

### 3.6 界面与交互

**R11 侧边栏收放**：侧边栏头部「« 收起」按钮收起（任务区占满窗口）；收起后标题栏左侧「» 展开」按钮恢复。收放状态**不持久化**，启动默认收起。

**R25 启动加载与错误提示**：启动时**异步加载**数据文件（不阻塞窗口）；文件缺失视为空数据；损坏 / 读取失败在界面顶部**红字提示**（"加载数据失败: …"）；**写盘失败**（IO 错误）同理提示，**绝不 panic**。

**R26 主题 / 语言 / 窗口**：深色主题（`Theme::Dark`）；界面文案全中文；窗口 880×640、最小 480×360；标题「待办清单 · Quick Todo」；中文渲染依赖系统字体回退（Windows 下微软雅黑）。

**R27 键盘交互**：表单输入框回车 = 提交（任务弹窗 / 项目弹窗 / 两个编辑表单）；任一弹窗打开时 **Esc 关闭当前弹窗**（与点击遮罩等效）；弹窗打开时**自动聚焦**首个输入框（任务弹窗→标题、项目弹窗→名称、项目内联编辑→名称）；点击遮罩关闭弹窗。

### 3.7 持久化与兼容

**R7 持久化**：任务 / 项目 / 排序偏好统一存**单个 JSON 文件**（Windows 默认 `%APPDATA%\quick-todo\todos.json`），每次数据变更后异步写盘（fire-and-forget），重启不丢。

**R25（补充）数据兼容**：
- 旧版**纯任务数组**格式自动迁移为 Store（项目列表为空），旧数据无损；
- 缺失 `description` / `project_id` / `due_at` / `priority` 字段的旧任务记录自动落空（`#[serde(default)]`）；
- 缺失 `started_at` / `finished_at` / `priority` 字段的旧项目记录自动落空；
- 缺失 `sort_mode` / `project_sort_mode` 的旧 Store 自动取默认「综合」；
- **数据目录重命名**（应用由 iced-demo 改名为 quick-todo）：新路径缺失时自动回退旧目录 `%APPDATA%\iced-todos\todos.json` 加载（一次性迁移，旧数据无损）。

## 4. 非功能需求

| N2   | 健壮性   | 数据文件缺失 / 损坏 / 读写失败均不崩溃，错误在 UI 提示                               |
| N3   | 兼容性   | 旧版数据文件（含多个演进版本）加载正常，自动迁移                                     |
| N4   | 性能     | 单文件 JSON、全量读写，数据量级（百级任务）下无需增量同步；实时耗时刷新粒度 1 秒     |
| N5   | 可维护性 | 分层职责单一（model / update / view / storage），纯函数状态更新，代码注释与文档中文  |
| N6   | 可测试性 | 核心逻辑纯函数化，单元测试 + 异步 IO 测试全绿（`cargo test`），`cargo clippy` 零警告 |
| N7   | 本地化   | UTC 存储、本地时区展示；日期时间输入接受 `YYYY-MM-DD` / `YYYY-MM-DD HH:MM[:SS]`      |

## 5. 验收标准

### 5.1 任务生命周期

1. `cargo test` 全部通过；`cargo build` 产出可执行文件，双击可运行。
2. 弹窗添加任务后立即显示创建时间（本地时区格式）；任务出现在未开始组最前。
3. 点击「开始」显示开始时间，且"已耗时"每秒递增；未开始任务不出现「完成」按钮。
4. 点击「完成」显示结束时间与总耗时，状态徽章变为"已完成"，任务移出双列进入归档。
5. 删除任务后列表与磁盘文件同步更新（任意状态、含归档内）。
6. 关闭程序再启动，任务列表与全部时间字段完整恢复。

### 5.2 项目与筛选

7. 弹窗新建项目（可带优先级与起止时间）出现在侧边栏并持久化；重名 / 空白名称被拒且弹窗保持打开、输入保留。
8. 任务可归属 / 切换 / 解除项目（经弹窗添加或编辑模式），重启后归属不丢。
9. 项目内联编辑保存即时生效并持久化；空名 / 重名（排除自身）/ 非法时间 / 开始≥结束被拒且保持编辑态；取消丢弃。
10. 删除项目后其下任务自动解除归属（任务保留），筛选与编辑态复位。
11. 侧边栏点击项目筛选任务（双列同时过滤）；「全部」显示所有任务。
12. 侧边栏收起 / 展开正常，重启后默认收起。

### 5.3 弹窗与表单

13. 三个弹窗（任务 / 项目 / 归档）互斥打开；半透明遮罩、点击遮罩 / Esc / 取消均可关闭并丢弃输入。
14. 任务弹窗可设置标题 / 描述 / 所属项目 / 优先级 / 截止时间；打开时聚焦标题输入框；标题为空或时间非法时「创建」禁用且红字提示；提交后任务插在最前、字段齐全、重启不丢。
15. 「快捷时间」（今天 / 明天 / 本周日 23:59）选中回填截止输入框，手动修改仍可覆盖；截止逾期且未完成的任务卡片标红。
16. 卡片默认只读展示全部属性；「编辑」进入编辑模式（主色描边），保存后卡片更新并持久化；空白标题 / 非法时间 / 项目不存在保存被拒且保持编辑模式；取消丢弃；切换编辑其他卡片丢弃未保存修改；时间字段与「开始 / 完成 / 删除」按钮不受影响。

### 5.4 分组、归档与排序

17. 双列分组：左=未开始、右=进行中，标题带计数、空组提示、各自独立滚动；组内按排序偏好排序（未设置均排最后）。
18. 「已完成 (N)」按钮打开归档弹窗：按完成时间降序展示（标题 / 项目 / 完成时间 / 总耗时），可删除。
19. 任务 / 项目排序下拉切换即时生效；「全部」行恒在项目列表最前；归档列表不受排序偏好影响。
20. 优先级设置与展示正确（任务徽章、项目圆点，高红 / 中橙 / 低灰，未设置不显示），重启后保留。

### 5.5 持久化与兼容

21. 排序偏好（任务 / 项目各自）持久化：切换后重启保持上次选择。
22. 旧版纯任务数组文件首次启动自动迁移（描述 / 归属 / 截止 / 优先级落空，项目为空）；旧 Store 无排序字段取默认「综合」；旧项目无起止时间字段自动落空；文件缺失视为空数据；损坏文件红字提示不崩溃。

## 7. 总体架构

### 7.1 模块划分

```
src/
├── main.rs     入口：iced::application 装配（boot / update / view / subscription）
├── model.rs    数据模型：Todo、Project、TodoStatus、App 及表单状态（纯数据，无 IO）
├── update.rs   Message 枚举 + update 纯函数（状态流转、校验、副作用派发）
├── view.rs     视图：侧边栏 + 双列任务区 + 卡片（只读 / 编辑模式）+ 三个弹窗
└── storage.rs  持久化：异步 JSON 读写（Store = 任务 + 项目 + 排序偏好，兼容旧格式）
docs/
└── 需求与概要设计.md     本文档
```

分层职责：**model = 纯数据、update = 纯逻辑、view = 渲染、storage = IO**；新增功能先判断归属，不跨层写代码。

### 7.2 数据流（Elm 架构）

**视图产生 Message → update 更新状态 → 视图重新渲染**；一次性副作用经 `Task`、持续流经 `Subscription` 注入，状态本身保持纯数据。

```
用户操作 ──► Message ──► update(&mut App, Message) ──► Task（异步落盘 / 聚焦）
                        │
                        ▼
                    App 状态（todos / projects / 表单 / now / 偏好）
                        │
                        ▼
                    view(&App) ──► Element 树 ──► 渲染
     每秒时钟 ◄── Subscription ◄── iced 运行时
     Esc 监听（弹窗打开时） ◄── Subscription ◄── iced 运行时
```

### 7.3 核心设计原则

1. **状态由时间字段推导，不存储状态枚举**（详见 8.2）——从结构上杜绝脏数据；
2. **update 是纯函数**：时间戳一律取自 `app.now`（每秒 Tick 刷新），不在 update 中调用 `Utc::now()`；副作用只通过返回的 `Task` 表达；
3. **时间统一 UTC 存储**，仅在 view 层用 `chrono::Local` 格式化展示；
4. **持久化 fire-and-forget**：每次状态变更后序列化整个 Store 异步写盘，成功静默、失败记入 `app.error`；不引入增量同步；
5. **非法状态流转静默拒绝**，不产生任何副作用；
6. **错误不崩溃**：文件缺失 = 空数据，损坏 = UI 提示；
7. **分组 / 排序是派生展示**，放 view 内部私有函数；update 层不改变列表顺序（仅插最前 / 删除 / 就地更新）。

## 8. 数据模型设计

### 8.1 领域模型

```rust
pub struct Todo {
    pub id: Uuid,                       // v7
    pub title: String,                  // trim 后非空
    #[serde(default)] pub description: String,   // 空串 = 无描述
    #[serde(default)] pub priority: Option<Priority>,   // None = 未设置
    #[serde(default)] pub project_id: Option<Uuid>,     // None = 未归属
    #[serde(default)] pub due_at: Option<DateTime<Utc>>, // None = 无截止
    pub created_at: DateTime<Utc>,      // 创建时写入，不可为空
    pub started_at: Option<DateTime<Utc>>,  // 点击"开始"时写入
    pub finished_at: Option<DateTime<Utc>>, // 点击"完成"时写入
}

pub struct Project {
    pub id: Uuid,
    pub name: String,                   // trim 后非空且不重名
    #[serde(default)] pub priority: Option<Priority>,
    #[serde(default)] pub started_at: Option<DateTime<Utc>>,
    #[serde(default)] pub finished_at: Option<DateTime<Utc>>,
    pub created_at: DateTime<Utc>,
}
```

> 所有可选字段带 `#[serde(default)]`：旧版数据文件缺字段时自动落空，**数据向后兼容**（见 9.2）。
> 新增字段（如 `priority`）一律带 `#[serde(default)]`，不得破坏旧数据。

**值类型**：

```rust
pub enum TodoStatus { Pending, InProgress, Done }   // 派生展示，不序列化
pub enum Priority { Low, Medium, High }             // 派生 Ord：低<中<高；Serialize/Deserialize
pub enum SortMode { Priority, Due, Combined }       // #[default] = Combined；JSON 存英文变体名
```

### 8.2 状态推导（核心设计决策）

**不单独存状态枚举，由时间字段推导**：

```rust
pub fn status(&self) -> TodoStatus {
    if self.finished_at.is_some() { TodoStatus::Done }
    else if self.started_at.is_some() { TodoStatus::InProgress }
    else { TodoStatus::Pending }
}
```

时间字段是**唯一事实来源**（single source of truth），从结构上杜绝"状态枚举与时间不一致"的脏数据（如 `finished_at` 已有值但状态仍是 Pending）。**严禁为 `Todo` 增加持久化的状态字段。**

```
创建（记录 created_at，插入列表最前）
   │
   ▼
Pending ──点击"开始"──► InProgress ──点击"完成"──► Done
（未开始）              （进行中）                  （已完成，移入归档）
   ▲                        │
   └────── 任意状态均可"删除" ┘
```

耗时计算 `duration(now)`：进行中 = `now - started_at`（实时）；已完成 = `finished_at - started_at`；未开始 = `None`。

### 8.3 排序键设计

排序是**派生展示**：view 层对任务 / 项目拷贝按排序键稳定排序，update 层不改列表顺序。所有排序键统一为"可选值排最后"的元组形态，直接按元组排序：

| 排序键                        | 形态                            | 语义                           |
| ----------------------------- | ------------------------------- | ------------------------------ |
| `Todo::priority_order_key`    | `(是否未设置, Reverse<优先级>)` | 高→低，未设置最后              |
| `Todo::due_order_key`         | `(是否无截止, 截止时间)`        | 截止升序，无截止最后           |
| `Todo::combined_order_key`    | 上述两者拼接                    | 优先级优先，同级按截止         |
| `Project::end_order_key`      | `(是否无结束, 结束时间)`        | 按**结束时间**升序（项目截止） |
| `Project::combined_order_key` | 优先级 + 结束时间               | 优先级优先，同级按结束         |

pub struct App {

**UI 状态与持久化状态的边界**（设计约定）：
- 侧边栏收放、三个弹窗、归档开关、两个编辑表单 = **纯内存**，不参与序列化；
- 排序偏好 = **例外**，随 Store 持久化、启动经 `Loaded` 恢复、切换即落盘。

### 8.5 表单状态（纯内存）

| 类型            | 字段                                                                               | 说明                                                                                                       |
| --------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `AddDialog`     | title / description / priority / project_id / due_input / due_parsed               | 任务弹窗；`due_parsed: Result<Option<DateTime<Utc>>, String>` 缓存**实时解析结果**（`Err` = 格式错误提示） |
| `ProjectDialog` | name / priority / start_input / start_parsed / end_input / end_parsed              | 项目弹窗；起止时间各自实时解析                                                                             |
| `ProjectEdit`   | project_id / name / priority / start_input / start_parsed / end_input / end_parsed | 项目内联编辑；打开时从项目字段**预填**（时间回填为可解析文本）                                             |
| `TodoEdit`      | todo_id / title / description / priority / project_id / due_input / due_parsed     | 卡片编辑模式；打开时预填全字段                                                                             |

设计要点：**输入文本与解析结果成对缓存**，输入变化即实时解析（非法格式立即红字提示），提交时复用缓存结果做最终校验——视图层与 update 层各自独立校验（view 用于禁用按钮，update 用于防御性拒绝）。

### 8.6 时间工具（model 层纯函数）

- `parse_datetime(&str) -> Result<Option<DateTime<Utc>>, String>`：空串 → `Ok(None)`；`YYYY-MM-DD HH:MM[:SS]` → 精确时刻；`YYYY-MM-DD` → 本地当天 **23:59:59**；其他 → `Err(格式提示)`。本地时区语义、存储转 UTC（DST 边界取最早映射）。
- `format_due(DateTime<Utc>) -> String`：UTC → 本地 `%Y-%m-%d %H:%M`（分钟粒度），保证 `parse_datetime(format_due(dt))` 闭环还原同一时刻。
- `QuickDue { Today, Tomorrow, Sunday }`：基于 `app.now` 计算本地日期当天 23:59 的回填文本（周日 = 本日时即今天）。
- `format_time`（view 层）：`%Y-%m-%d %H:%M:%S` 本地展示。
- `format_duration`（view 层）：`X 小时 Y 分 Z 秒` / `Y 分 Z 秒` / `Z 秒`。

## 9. 持久化设计

### 9.1 存储位置与格式

```rust
pub struct Store {
    pub todos: Vec<Todo>,
    pub projects: Vec<Project>,
    #[serde(default)] pub sort_mode: SortMode,          // 缺省 Combined
    #[serde(default)] pub project_sort_mode: SortMode,  // 缺省 Combined
}
```

- 路径：`directories::ProjectDirs::from("dev", "quick-todo", "quick-todo").data_dir()/todos.json`（Windows = `%APPDATA%\quick-todo\todos.json`），无法确定系统目录时退化到当前目录 `todos.json`；重命名前的旧目录（`%APPDATA%\iced-todos`）若有 `todos.json` 且新路径缺失，`load` 自动回退旧路径加载（一次性迁移）；
- 序列化：`serde_json::to_string_pretty`，时间字段以 ISO-8601 UTC（`2026-01-31T15:30:00Z`）存储，`SortMode` 存英文变体名（`"Combined"`）；
- 写入：`tokio::fs::write`（自动创建父目录）。

### 9.2 兼容与迁移策略

```
load()（默认路径）:
  ├─ 新路径有文件                    → 按 load_from 逻辑解析（优先，不再看旧路径）
  ├─ 新路径缺失（NotFound）          → 回退旧路径（重命名前目录）→ load_from
  └─ 其他 IO 错误                    → Err                            # UI 红字提示

load_from(path):
  ├─ 文件不存在（NotFound）        → Ok(Store::default())          # 空数据
  ├─ 读取成功：
  │    ├─ 解析 Store 成功          → 直接使用
  │    ├─ 解析 Store 失败          → 回退解析旧版 Vec<Todo>：
  │    │                            └─ 成功 → Store { todos, projects: [] }（自动迁移）
  │    └─ 两种都失败               → Err(带路径的解析错误)          # UI 红字提示
  └─ 其他 IO 错误                  → Err                            # UI 红字提示
```

旧格式演进一览（缺字段自动落空，`#[serde(default)]`）：

| 演进点                      | 旧数据表现   | 迁移结果        |
| --------------------------- | ------------ | --------------- |
| 版本一 → Store              | 纯任务数组   | `projects` 为空 |
| 描述 / 归属 / 截止 / 优先级 | 任务缺字段   | `""` / `None`   |
| 项目优先级 / 起止时间       | 项目缺字段   | `None`          |
| 排序偏好                    | Store 缺字段 | `Combined`      |
| 数据目录重命名              | 新路径无文件，旧目录有 `todos.json` | 回退旧路径加载（一次性） |

### 9.3 读写策略

- **加载**：`boot` 返回 `Task::perform(storage::load(), Message::Loaded)`，不阻塞窗口启动；`Loaded(Ok)` 填充 todos / projects / 排序偏好，`Loaded(Err)` 记入 `app.error`；
- **保存**：`update` 中数据变更后调用 `persist(app)`——克隆 Store、序列化、`Task::perform(storage::save, Message::Saved)` fire-and-forget；`Saved(Ok)` 静默，`Saved(Err)` 记入 `app.error`；
- **触发落盘的变更**：任务（添加 / 开始 / 完成 / 删除 / 编辑保存）、项目（创建 / 编辑保存 / 删除）、排序偏好切换；
- **不触发落盘的变更**：弹窗打开 / 关闭 / 输入、筛选、侧边栏收放、编辑表单输入、Tick。

## 10. 消息与状态流转设计

### 10.2 校验规则（update 层防御性校验，view 层同步禁用按钮）

| 场景         | 校验                                                                 | 失败行为                       |
| ------------ | -------------------------------------------------------------------- | ------------------------------ |
| 任务弹窗提交 | 标题 trim 非空；`due_parsed` 为 `Ok`；项目存在（`None` 或命中）      | 恢复弹窗（输入保留），无副作用 |
| 任务编辑保存 | 同上（标题 trim、时间合法、项目存在）                                | 保持编辑态（输入保留）         |
| 项目弹窗提交 | 名称 trim 非空且不重名；起止时间各自 `Ok`；同时设置时 start < finish | 恢复弹窗（输入保留）           |
| 项目编辑保存 | 同上，**重名校验排除自身**                                           | 保持编辑态（输入保留）         |
| 状态流转     | 仅 Pending 可开始、仅 InProgress 可完成                              | 静默拒绝                       |
| 防御性       | 弹窗 / 编辑未打开时收到输入或提交消息                                | 忽略（`Task::none()`）         |
| 防御性       | 项目 / 任务下拉选择不存在的 id                                       | 拒绝                           |

> 注：所有提交类消息在 `take()` 表单后用闭包 `restore` 恢复——保证校验失败时表单内容（含错误提示）完整保留。

### 10.3 副作用设计

- **一次性**：异步落盘（`Task::perform`）、输入框聚焦（`iced::widget::operation::focus`，返回的 Task 在下一次渲染时生效）；
- **持续流**：`Subscription::run(|| iced::stream::channel(1, ...))` 每秒推送 `Utc::now()` → `Tick`；**发送失败（应用退出）必须 break 结束流**；
- **条件订阅**：任一弹窗打开时追加 `iced::event::listen_with` 监听 Esc → `CloseActiveDialog`（`listen_with` 只接受无捕获 fn 指针，固定发 `CloseActiveDialog`，由 update 分派到当前打开的弹窗）。

### 11.1 整体布局

```
┌───────────┬──────────────────────────────────────────────┐

│            │ │ 项目：工作       │ │ 项目：无项目             │ │

│            │ └────────────┘ │ └────────────────────────┘ │

│ [已完成 (1)] ├───────────────┴────────────────────────────┤
└───────────┴──────────────────────────────────────────────┘
```

- 窗口 880×640、最小 480×360、深色主题；侧边栏固定宽 220px；
- 标题栏：收起时左侧「» 展开」按钮，展开时无；右端「＋ 添加任务」（唯一添加入口）+ 摘要（`共 N 项 · 进行中 X · 已完成 Y`）；
- 错误提示（`app.error`）显示在标题栏下方红字。

### 11.2 组件规格

**项目侧边栏**：「项目」标题 + 「« 收起」+「＋ 添加项目」+ 排序下拉 + 可滚动项目列表 + 底部「已完成 (N)」。
项目行：优先级圆点（● 高红/中橙/低灰）+ 名称按钮（选中主色描边高亮）+ 计数 + 编辑 / 删除（文字按钮）+ 起止时间小字（`01-01 ~ 01-31`，仅显示已设置端）；「全部」行无圆点 / 编辑 / 删除，恒在列表最前。编辑态原位展开内联表单（名称 / 开始 / 结束 / 优先级 + 保存 / 取消，实时校验红字）。

**任务区双列**：`grouped_columns` 过滤当前筛选 → 按状态分列 → 组内按 `sort_mode` 稳定排序 → `row![左列, 右列]`；每列 = 标题（带计数）+ 独立 `scrollable`。空态：整区空 →「暂无任务，先添加一个吧」/「该项目暂无任务」；组内空 →「暂无未开始任务」/「暂无进行中任务」。

**任务卡片（只读）**：头部 = 标题 + 优先级徽章 + 状态徽章 + 操作按钮（未开始：「开始」+「删除」；进行中：「完成」+「删除」；已完成卡片不出现在双列）；正文 = 描述（非空时灰字）+ 元信息行（项目 / 截止时间 / 创建时间 / 已耗时 / 结束时间 / 总耗时）；右下角「编辑」。

**卡片编辑模式**：主色描边（1.5px）；标题输入（必填）+ 描述输入 + 项目下拉 + 优先级下拉 + 截止时间输入 + 快捷时间下拉 + 红字错误提示；底部右下角「保存 / 取消」；下方保留**只读**时间元信息（时间字段永不直接编辑）。

**弹窗（三个共用叠加层）**：`stack![底层内容, mouse_area(半透明遮罩).on_press(CloseActiveDialog), container(opaque(card)).center]`——遮罩点击关闭、`opaque` 防事件穿透。**任务弹窗宽 460、项目弹窗宽 460、归档弹窗 520×480**。表单字段与校验见 10.2；「创建 / 保存」用 `on_press_maybe` 在非法时禁用。
