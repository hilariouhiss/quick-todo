# Iced Todos 桌面应用 · 设计方案

## 1. 需求

使用 [Iced](https://iced.rs) 框架开发一个简单的 todos（待办清单）桌面程序，核心要求：

| 编号 | 需求         | 说明                                                             |
| ---- | ------------ | ---------------------------------------------------------------- |
| R1   | 添加任务     | 输入标题，回车或点击"添加"创建任务                               |
| R2   | 记录创建时间 | 任务创建时**自动**记录 `created_at`，不可为空                    |
| R3   | 记录开始时间 | 点击"开始"时记录 `started_at`（仅未开始任务可触发）              |
| R4   | 记录结束时间 | 点击"完成"时记录 `finished_at`（仅进行中任务可触发）             |
| R5   | 删除任务     | 任意状态的任务均可删除                                           |
| R6   | 时间展示     | 每个任务展示创建/开始/结束三个时间点；进行中任务显示**实时**耗时 |
| R7   | 持久化       | 任务列表落盘，重启程序后数据不丢失                               |
| R8   | 任务归属项目 | 每条任务可归属 **0 或 1 个**项目，卡片上可随时选择 / 切换 / 解除 |
| R9   | 项目增删查改 | 创建、查看（侧边栏列表）、重命名（内联编辑）、删除项目           |
| R10  | 按项目筛选   | 侧边栏点击项目过滤任务列表；"全部"视图保留                     |

## 2. 技术选型

| 项       | 选择                                                | 理由                                                                 |
| -------- | --------------------------------------------------- | -------------------------------------------------------------------- |
| UI 框架  | iced 0.14（`tokio` / `debug` / `time-travel` 特性） | 项目已配置；Elm 架构，纯函数式状态更新                               |
| 时间戳   | chrono 0.4（`serde` 特性）                          | 标准库无墙上时钟；chrono 提供 `DateTime<Utc>` 序列化与本地时区格式化 |
| 任务 ID  | uuid v7                                             | 时间有序、无需全局状态                                               |
| 持久化   | serde_json + tokio::fs + directories                | JSON 人类可读、易调试；异步 IO 不阻塞 UI 线程                        |
| 数据目录 | `%APPDATA%\iced-todos\todos.json`（Windows）        | `directories::ProjectDirs` 提供跨平台应用数据目录                    |

## 3. 总体架构

```
src/
├── main.rs     入口：iced::application 装配（boot / update / view / subscription）
├── model.rs    数据模型：Todo、Project、TodoStatus、App 状态
├── update.rs   Message 枚举 + update 纯函数（状态流转、副作用派发）
├── view.rs     视图：项目侧边栏 + 任务区（输入行、任务卡片、时间元信息）
└── storage.rs  持久化：异步 JSON 读写（Store = 任务 + 项目，兼容旧格式）
docs/
└── 方案.md     本设计文档
```

数据流遵循 Elm 架构：**视图产生消息 → update 更新状态 → 视图重新渲染**，异步副作用通过 `Task`（一次性）与 `Subscription`（持续流）注入，状态本身保持纯数据。

```
用户操作 ──► Message ──► update(&mut App, Message) ──► Task（异步落盘）
                        │
                        ▼
                    App 状态（todos / input / now）
                        │
                        ▼
                    view(&App) ──► Element 树 ──► 渲染
     每秒时钟 ◄── Subscription ◄── iced 运行时
```

## 4. 数据模型

### 4.1 时间点与状态：状态由时间推导

```rust
pub struct Todo {
    pub id: Uuid,
    pub title: String,
    pub project_id: Option<Uuid>,       // R8：所属项目（None = 未归属），serde 缺省兼容旧数据
    pub created_at: DateTime<Utc>,      // R2：创建时间，创建时写入，不可为空
    pub started_at: Option<DateTime<Utc>>,  // R3：开始时间，点击"开始"时写入
    pub finished_at: Option<DateTime<Utc>>, // R4：结束时间，点击"完成"时写入
}

pub struct Project {
    pub id: Uuid,
    pub name: String,                   // 项目名，trim 后非空且不与其他项目重名
    pub created_at: DateTime<Utc>,      // 创建时间
}
```

> `project_id` 带 `#[serde(default)]`：旧版数据文件没有该字段，反序列化时自动落空（`None`）。
> 项目归属不引入状态机，`project_id` 为 `None` 即未归属，删除项目时其下任务统一解除归属。

**设计决策：不单独存状态枚举，而是由时间字段推导**：

```rust
pub fn status(&self) -> TodoStatus {
    if self.finished_at.is_some() { Done }
    else if self.started_at.is_some() { InProgress }
    else { Pending }
}
```

好处：时间字段是唯一事实来源（single source of truth），从结构上杜绝"状态枚举与时间不一致"的脏数据（例如 `finished_at` 已有值但状态仍是 `Pending`）。状态机：

```
创建（记录 created_at）
   │
   ▼
Pending ──点击"开始"──► InProgress ──点击"完成"──► Done
（未开始）              （进行中）                  （已完成）
   ▲                        │
   └────── 任意状态均可"删除" ┘
```

### 4.2 存储格式（todos.json）

数据文件路径不变，格式升级为任务 + 项目统一存储：

```json
{
  "todos": [
    {
      "id": "0195c7e0-...-v7",
      "title": "写设计方案",
      "project_id": "0195c7f0-...-v7",
      "created_at": "2026-01-01T10:00:00Z",
      "started_at": "2026-01-01T10:05:00Z",
      "finished_at": null
    }
  ],
  "projects": [
    { "id": "0195c7f0-...-v7", "name": "工作", "created_at": "2026-01-01T09:00:00Z" }
  ]
}
```

- 时间以 **UTC** 存储（规范、无时区歧义），展示时转换为本地时区（`%Y-%m-%d %H:%M:%S`）。
- **旧格式兼容**：加载时先尝试解析 `Store`，失败则回退解析旧版纯任务数组 `Vec<Todo>`，成功即自动迁移（`projects` 为空）——旧数据无损。
- 文件缺失视为空数据；解析失败给出错误提示而非崩溃。

## 5. 消息与副作用

### 5.1 Message 枚举

| 消息                                | 触发               | 状态变更                                   |
| ----------------------------------- | ------------------ | ------------------------------------------ |
| `InputChanged(String)`              | 输入框文本变化     | 更新 `input`                               |
| `AddTodo`                           | 回车 / 点击"添加"  | 新建 Todo（记录 `created_at`），清空输入框 |
| `StartTodo(id)`                     | 点击"开始"         | 写入 `started_at`（仅 Pending 有效）       |
| `FinishTodo(id)`                    | 点击"完成"         | 写入 `finished_at`（仅 InProgress 有效）   |
| `DeleteTodo(id)`                    | 点击"删除"         | 从列表移除                                 |
| `Loaded(Result<Store, String>)` | 启动时异步加载完成 | 填充 `todos` + `projects` 或记录错误 |
| `Saved(Result<(), String>)`     | 异步保存完成       | 记录错误（成功则静默）                     |
| `Tick(DateTime<Utc>)`           | 每秒时钟订阅       | 刷新 `app.now`，驱动实时耗时               |
| `ProjectInputChanged(String)`   | 新建项目输入框变化 | 更新 `project_input`                       |
| `AddProject`                    | 回车 / 点击"添加"  | trim 非空且不重名 → 新建项目、清空输入、落盘 |
| `StartRenameProject(id)`        | 点击"编辑"        | 进入内联编辑态并预填名称                   |
| `ProjectRenameChanged(String)`  | 重命名输入框变化   | 更新 `project_edit_input`                  |
| `SaveRenameProject`             | 点击"保存" / 回车  | 校验（非空、不重名）→ 提交；非法保持编辑态 |
| `CancelRenameProject`           | 点击"取消"        | 退出编辑态                                 |
| `DeleteProject(id)`             | 点击"删除"        | 删除项目 + 解除其下任务归属 + 复位筛选/编辑态 |
| `SelectProject(Option<Uuid>)`   | 点击侧边栏项目行   | 设置筛选（`None` = 全部）                  |
| `AssignProject { todo_id, project_id }` | 卡片项目下拉选择 | 设置/解除归属（校验项目存在；值未变不落盘） |

### 5.2 副作用设计

- **保存**：每次变更后把整个 `Store`（任务 + 项目）序列化，通过 `Task::perform` 异步写盘（fire-and-forget，成功消息仅用于报错）。数据量小（单文件 JSON），不做增量同步；简单可靠。
- **加载**：`boot` 阶段返回 `Task::perform(storage::load(), Message::Loaded)`，不阻塞窗口启动。
- **时钟**：`Subscription::run(|| iced::stream::channel(...))` 每秒推送 `Utc::now()`，让"进行中"任务的耗时实时刷新（1 秒粒度）。

## 6. 视图设计

```
┌───────────┬──────────────────────────────────────┐
│ 项目       │ 待办清单               共 3 项 · … │   ← 标题 + 摘要
│ [新建项目…] [添加] │ [输入任务内容…]     [添加] │   ← 输入行
│ 全部 (3)   ├──────────────────────────────────────┤
│ ● 工作 (1) │ ┌ 写设计方案     ● 进行中 [完成][删除] │   ← 任务卡片
│   生活 (2) │ │ 项目 [工作 ▾]                      │   ← 归属选择器
│            │ │ 创建时间 2026-01-01 10:00:00      │
│            │ │ 已耗时 2 分 15 秒（实时）           │
│            │ └────────────────────────────────────┘
│            │ …（列表可滚动；按选中项目过滤）        │
└───────────┴──────────────────────────────────────┘
```

- 左侧**项目侧边栏**（固定宽 220px）：新建输入行 + 可滚动项目列表；
  项目行显示名称与任务计数，点击名称筛选（选中高亮），`✎` 编辑（行内重命名）/ `删除`。
- 任务卡片元信息区新增"项目"行：下拉（pick_list）选择 / 切换 / 解除归属。
- 新任务插在列表最前；列表区域可滚动；空列表显示提示文案（区分"暂无任务"与"该项目暂无任务"）。
- 状态徽章配色：未开始＝灰、进行中＝橙、已完成＝绿；卡片与侧边栏底色取自主题扩展调色板，深浅主题自适应。
- 窗口 880×640、最小 480×360，深色主题（`Theme::Dark`）。
- 中文渲染依赖系统字体回退（iced 默认加载系统字体，Windows 下自动回退到微软雅黑）。

## 7. 测试策略

- **model**：时间字段与状态推导、耗时计算、UUID 唯一性、项目创建时间 —— 纯逻辑单元测试。
- **update**：任务（添加去空白、记录创建时间、非法状态流转被拒绝、删除、最新在前）；
  项目（添加去空白 / 拒重名、重命名预填与校验、取消编辑、删除解除归属并复位筛选、归属设置与解除、未知项目拒绝）—— 纯函数测试。
- **storage**：Store 往返一致（含项目归属）、旧版纯数组自动迁移、文件缺失返回空数据、损坏文件返回错误 —— `#[tokio::test]` 使用临时目录。

## 8. 验收标准

1. `cargo test` 全部通过；`cargo build` 产出可执行文件，双击可运行。
2. 添加任务后立即显示创建时间（本地时区格式）。
3. 点击"开始"显示开始时间，且"已耗时"每秒递增。
4. 点击"完成"显示结束时间与总耗时，状态徽章变为"已完成"。
5. 未开始的任务无法直接完成（按钮不出现）。
6. 关闭程序再启动，任务列表与全部时间字段完整恢复。
7. 删除任务后列表与磁盘文件同步更新。
8. 新建项目出现在侧边栏并持久化，重启后仍在；重名 / 空白项目名被拒绝。
9. 任务可归属 / 切换 / 解除项目，卡片下拉显示当前项目，重启后归属不丢。
10. 重命名项目即时生效并持久化；空名 / 重名被拒绝且保持编辑态。
11. 删除项目后其下任务自动解除归属（任务本身保留），筛选与编辑态复位。
12. 侧边栏点击项目可筛选任务；"全部"显示所有任务；旧版数据文件首次启动自动迁移。
