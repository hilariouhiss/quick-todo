# Iced Todos 桌面应用 · 设计方案

## 1. 需求

使用 [Iced](https://iced.rs) 框架开发一个简单的 todos（待办清单）桌面程序，核心要求：

| 编号 | 需求         | 说明                                                             |
| ---- | ------------ | ---------------------------------------------------------------- |
| R1   | 添加任务     | 输入标题，回车或点击"添加"创建任务                               |
| R2   | 记录创建时间 | 任务创建时**自动**记录 `created_at`，不可为空                    |
| R3   | 记录开始时间 | 点击"开始"时记录 `started_at`（仅未开始任务可触发）              |
| R4   | 记录结束时间 | 点击"完成"时记录 `finished_at`（仅进行中任务可触发）             |
| R5   | 删除任务     | 任意状态的任务均可删除                                           |
| R6   | 时间展示     | 每个任务展示创建/开始/结束三个时间点；进行中任务显示**实时**耗时 |
| R7   | 持久化       | 任务列表落盘，重启程序后数据不丢失                               |
| R8   | 任务归属项目 | 每条任务可归属 **0 或 1 个**项目，卡片上可随时选择 / 切换 / 解除 |
| R9   | 项目增删查改 | 创建（弹窗）、查看（侧边栏列表）、编辑（侧边栏内联表单：名称 + 起止时间）、删除项目 |
| R10  | 按项目筛选   | 侧边栏点击项目过滤任务列表；"全部"视图保留                     |
| R11  | 侧边栏收放   | 项目侧边栏可收起 / 展开；状态不持久化，启动默认收起             |
| R12  | 任务描述     | 任务可带可选描述文本：通过「详细添加…」弹窗填写，卡片上只读显示；快捷添加仅标题 |
| R13  | 弹窗添加任务 | 点击标题栏「＋ 添加任务」弹出模态弹窗（**唯一添加方式**）：标题（必填）、描述、所属项目、截止时间 |
| R14  | 截止时间     | 任务可带 `due_at` 截止时间：持久化、卡片展示、未完成且逾期标红提示 |
| R15  | 编辑任务     | 卡片默认**只读**展示全部属性（含项目名）；点击「编辑」进入该卡片的可编辑模式（即“当前任务”），标题 / 描述 / 项目 / 截止时间可修改，保存校验同弹窗，其余卡片保持只读 |
| R16  | 项目起止时间 | 项目可带可选**开始 / 结束**时间：弹窗添加、侧边栏内联编辑均可设置，项目行小字展示；开始必须早于结束 |
| R17  | 项目弹窗添加 | 侧边栏「＋ 添加项目」按钮弹出模态弹窗添加项目：名称（必填）+ 可选起止时间；校验（空白/重名/格式非法/开始≥结束）失败保持弹窗并红字提示 |
| R18  | 双列分组显示 | 任务区两列：**左列=未开始、右列=进行中**（各自独立滚动、标题带计数）；组内按**截止时间升序**（无截止排后）；任务状态变更后自动归位 |
| R19  | 已完成归档   | 已完成任务不进双列：侧边栏「已完成 (N)」按钮打开归档弹窗，按**完成时间降序**展示，可删除 |
| R20  | 项目内联编辑 | 侧边栏项目「编辑」原位展开表单：名称 + 开始/结束时间可改，重名（排除自身）/ 空白 / 格式非法 / 开始≥结束 被拒并保持编辑态 |
| R21  | 任务优先级   | 任务可带可选**优先级**（无 / 低 / 中 / 高）：弹窗添加与卡片编辑模式可设置，卡片头部徽章展示（高红 / 中橙 / 低灰） |
| R22  | 任务排序     | 任务两列可切换排序：**优先级**（高→低、未设置最后）/ **截止日期**（升序）/ **综合**（优先级优先、同级按截止）；偏好**持久化** |
| R23  | 项目优先级   | 项目可带可选**优先级**：弹窗添加与内联编辑可设置，侧边栏行内彩色圆点展示 |
| R24  | 项目排序     | 侧边栏项目列表可切换排序：优先级 / 截止日期（项目结束时间）/ 综合；「全部」行恒在最前；偏好**持久化** |

## 2. 技术选型

| 项       | 选择                                                | 理由                                                                 |
| -------- | --------------------------------------------------- | -------------------------------------------------------------------- |
| UI 框架  | iced 0.14（`tokio` / `debug` / `time-travel` 特性） | 项目已配置；Elm 架构，纯函数式状态更新                               |
| 时间戳   | chrono 0.4（`serde` 特性）                          | 标准库无墙上时钟；chrono 提供 `DateTime<Utc>` 序列化与本地时区格式化 |
| 任务 ID  | uuid v7                                             | 时间有序、无需全局状态                                               |
| 持久化   | serde_json + tokio::fs + directories                | JSON 人类可读、易调试；异步 IO 不阻塞 UI 线程                        |
| 数据目录 | `%APPDATA%\iced-todos\todos.json`（Windows）        | `directories::ProjectDirs` 提供跨平台应用数据目录                    |

## 3. 总体架构

```
src/
├── main.rs     入口：iced::application 装配（boot / update / view / subscription）
├── model.rs    数据模型：Todo、Project、TodoStatus、App 状态
├── update.rs   Message 枚举 + update 纯函数（状态流转、副作用派发）
├── view.rs     视图：项目侧边栏 + 任务区（输入行、任务卡片、时间元信息）
└── storage.rs  持久化：异步 JSON 读写（Store = 任务 + 项目，兼容旧格式）
docs/
└── 方案.md     本设计文档
```

数据流遵循 Elm 架构：**视图产生消息 → update 更新状态 → 视图重新渲染**，异步副作用通过 `Task`（一次性）与 `Subscription`（持续流）注入，状态本身保持纯数据。

```
用户操作 ──► Message ──► update(&mut App, Message) ──► Task（异步落盘）
                        │
                        ▼
                    App 状态（todos / input / now）
                        │
                        ▼
                    view(&App) ──► Element 树 ──► 渲染
     每秒时钟 ◄── Subscription ◄── iced 运行时
```

## 4. 数据模型

### 4.1 时间点与状态：状态由时间推导

```rust
pub struct Todo {
    pub id: Uuid,
    pub title: String,
    pub description: String,        // R12：可选描述，空串 = 无描述，serde 缺省兼容旧数据
    pub project_id: Option<Uuid>,       // R8：所属项目（None = 未归属），serde 缺省兼容旧数据
    pub due_at: Option<DateTime<Utc>>,  // R14：截止时间（None = 无截止），serde 缺省兼容旧数据
    pub created_at: DateTime<Utc>,      // R2：创建时间，创建时写入，不可为空
    pub started_at: Option<DateTime<Utc>>,  // R3：开始时间，点击"开始"时写入
    pub finished_at: Option<DateTime<Utc>>, // R4：结束时间，点击"完成"时写入
}

pub struct Project {
    pub id: Uuid,
    pub name: String,                   // 项目名，trim 后非空且不与其他项目重名
    pub created_at: DateTime<Utc>,      // 创建时间
}
```

> `description` / `project_id` / `due_at` 均带 `#[serde(default)]`：旧版数据文件没有这些字段，反序列化时自动落空（空串 / `None`）。
> 项目归属不引入状态机，`project_id` 为 `None` 即未归属，删除项目时其下任务统一解除归属。

**设计决策：不单独存状态枚举，而是由时间字段推导**：

```rust
pub fn status(&self) -> TodoStatus {
    if self.finished_at.is_some() { Done }
    else if self.started_at.is_some() { InProgress }
    else { Pending }
}
```

好处：时间字段是唯一事实来源（single source of truth），从结构上杜绝"状态枚举与时间不一致"的脏数据（例如 `finished_at` 已有值但状态仍是 `Pending`）。状态机：

```
创建（记录 created_at）
   │
   ▼
Pending ──点击"开始"──► InProgress ──点击"完成"──► Done
（未开始）              （进行中）                  （已完成）
   ▲                        │
   └────── 任意状态均可"删除" ┘
```

### 4.2 存储格式（todos.json）

数据文件路径不变，格式升级为任务 + 项目统一存储：

```json
{
  "todos": [
    {
      "id": "0195c7e0-...-v7",
      "title": "写设计方案",
      "description": "先读需求再动手",
      "priority": "High",
      "project_id": "0195c7f0-...-v7",
      "due_at": "2026-01-31T15:30:00Z",
      "created_at": "2026-01-01T10:00:00Z",
      "started_at": "2026-01-01T10:05:00Z",
      "finished_at": null
    }
  ],
  "projects": [
    { "id": "0195c7f0-...-v7", "name": "工作", "priority": "High", "started_at": "2026-01-01T00:00:00Z", "finished_at": "2026-01-31T15:30:00Z", "created_at": "2026-01-01T09:00:00Z" }
  ],
  "sort_mode": "Combined",
  "project_sort_mode": "Combined"
}
```

- 时间以 **UTC** 存储（规范、无时区歧义），展示时转换为本地时区（`%Y-%m-%d %H:%M:%S`）。
- **旧格式兼容**：加载时先尝试解析 `Store`，失败则回退解析旧版纯任务数组 `Vec<Todo>`，成功即自动迁移（`projects` 为空）——旧数据无损；缺失 `description` / `project_id` / `priority` 字段的旧记录自动落空；缺失 `started_at` / `finished_at` 的项目自动落空；缺失 `sort_mode` / `project_sort_mode` 的旧 Store 自动取默认「综合」（`#[serde(default)]`）。
- 文件缺失视为空数据；解析失败给出错误提示而非崩溃。

### 5.2 副作用设计

- **保存**：每次变更后把整个 `Store`（任务 + 项目）序列化，通过 `Task::perform` 异步写盘（fire-and-forget，成功消息仅用于报错）。数据量小（单文件 JSON），不做增量同步；简单可靠。
- **加载**：`boot` 阶段返回 `Task::perform(storage::load(), Message::Loaded)`，不阻塞窗口启动。
- **时钟**：`Subscription::run(|| iced::stream::channel(...))` 每秒推送 `Utc::now()`，让"进行中"任务的耗时实时刷新（1 秒粒度）。

## 6. 视图设计

```
┌───────────┬──────────────────────────────────────┐
│ 项目   «  │ » 待办清单              共 3 项 · … [＋添加任务] │   ← 标题 + 摘要 + 唯一添加入口
│ [＋添加项目] │             排序：[综合 ▾]          │   ← 任务排序（优先级/截止/综合）
│ 排序：[综合▾] ├──────────────┬───────────────────────┤
│ 全部 (3)   │ 未开始 (2)    │ 进行中 (1)             │   ← 左列 / 右列（各自滚动）
│ ● 工作 (1) │ ┌──────────┐ │ ┌───────────────────┐ │
│   生活 (2) │ │ 写周报    │ │ │ 写设计方案          │ │
│            │ │ [高]截止01-31│ │ │ [中] 已耗时 2 分 15 秒 │ │
│            │ │   [编辑]  │ │ │          [编辑]     │ │
│            │ └──────────┘ │ └───────────────────┘ │
│            │ …（组内按排序偏好）                  │
│ [已完成 (1)] ├──────────────┴───────────────────────┤
└───────────┴──────────────────────────────────────┘
```

- 左侧**项目侧边栏**（固定宽 220px）：「＋ 添加项目」按钮 + 「排序」下拉（优先级 / 截止日期 / 综合）+ 可滚动项目列表 + 底部「已完成 (N)」按钮；
  项目行显示**优先级圆点**（高红 / 中橙 / 低灰，未设置不显示）、名称与任务计数，点击名称筛选（选中高亮），`✎` 编辑（原位展开表单：名称 + 起止时间 + 优先级 + 保存/取消）/ `删除`；
  设置了起止时间的项目在名称行下方小字显示（如 `01-01 ~ 01-31`，仅显示已设置的一端）。
  头部右侧「«」收起侧边栏；收起后标题栏左侧「» 展开」；收放状态**不持久化**，启动默认收起。
- **双列分组**（R18）：任务区一行两列（各占半宽，独立滚动）——左列=未开始、右列=进行中；
  每组标题带计数（如「未开始 (2)」），空组显示灰色提示；**组内排序按 `sort_mode`**（R22：优先级高→低 / 截止日期升序 / 综合=优先级优先同级按截止，未设置均排最后），
  状态变更 / 截止时间编辑后位置自动就位；项目筛选作用于两列；全部为空时显示单一"暂无任务"提示。
- **任务优先级**（R21）：卡片头部状态徽章旁显示「高 / 中 / 低」小字徽章（高红 / 中橙 / 低灰），未设置不显示；
  任务弹窗与卡片编辑模式均可设置（下拉：无 / 低 / 中 / 高）。
- **已完成归档**（R19）：已完成任务不进双列；侧边栏「已完成 (N)」按钮打开归档弹窗（模态），
  按完成时间**降序**列出紧凑行（标题 / 项目 / 完成时间 / 总耗时 + 删除），列表可滚动（不受排序偏好影响）。
- 任务卡片元信息区"项目"行默认**只读文字**展示（未归属显示"无项目"），不再直接可改；
  「编辑」按钮位于卡片**右下角**；点击进入可编辑模式（该卡片即"当前任务"）：标题 / 描述 / 项目（下拉）/ 截止时间（输入 + 快捷时间）均可修改，
  「保存 / 取消」同样位于卡片底部右下角（与「编辑」对称），保存校验（标题非空、时间格式合法、项目存在）通过后更新任务并落盘，取消丢弃；
  编辑模式用主题主色描边区分，时间字段保持只读。编辑表单是纯 UI 状态（`App.todo_edit`），不参与持久化；切换编辑其他卡片时，未保存的修改被丢弃。
- 新任务插在列表最前（= 未开始组内、同截止时间时在前）；任务区双列各自滚动；
- **统一弹窗添加**（R13）：标题栏「＋ 添加任务」按钮弹出模态弹窗，为**唯一添加方式**（顶部快捷输入行与「详细添加…」已移除）。
  iced 0.14 无内置 Modal，用 `stack`（底层内容 + 半透明遮罩 `mouse_area` + 居中卡片 `opaque`）实现：
  点击遮罩关闭、Esc 关闭、取消丢弃；弹窗打开时自动聚焦标题输入框。
  弹窗表单：标题（必填）/ 描述 / 所属项目（下拉，预选当前筛选项目）/ 截止时间
  （文本输入实时校验 + 「快捷时间」下拉：今天 / 明天 / 本周日 23:59，回填后可手动改）。
  标题为空或时间格式非法时「创建」禁用并红字提示；提交成功插在列表最前、记录 `app.now`。
- **项目弹窗添加**（R17）：侧边栏「＋ 添加项目」按钮弹出模态弹窗（与任务 / 归档弹窗共用叠加层，三弹窗互斥打开）：
  名称（必填，trim 非空且不重名）+ 可选开始 / 结束时间（复用 `parse_datetime` 解析，格式 `2026-01-31` 或 `2026-01-31 18:30`）。
  名称为空 / 重名 / 时间格式非法 / 开始≥结束时「创建」禁用并红字提示；提交成功创建项目（含起止时间）并落盘；
  遮罩 / Esc / 取消关闭并丢弃输入；打开时自动聚焦名称输入框；弹窗表单是纯 UI 状态（`App.project_dialog`），不参与持久化。
- **项目内联编辑**（R20）：项目行「编辑」原位展开表单：名称 + 开始 / 结束时间 + 保存 / 取消，
  校验（名称非空且不重名（排除自身）、时间格式合法、开始早于结束）失败红字提示并保持编辑态；
  编辑表单是纯 UI 状态（`App.project_edit`），不参与持久化；保存成功就地更新并落盘。
- **项目起止时间展示**（R16）：侧边栏项目行名称下方小字显示（如 `01-01 ~ 01-31`，仅显示已设置的一端）；弹窗添加、内联编辑均可设置。
- **截止时间展示**（R14）：卡片元信息区项目行下方显示「截止时间」；
  未完成且已逾期的任务标红，其余灰色；无截止时间不显示该行。
- 状态徽章配色：未开始＝灰、进行中＝橙、已完成＝绿；卡片与侧边栏底色取自主题扩展调色板，深浅主题自适应。
- 窗口 880×640、最小 480×360，深色主题（`Theme::Dark`）。
- 中文渲染依赖系统字体回退（iced 默认加载系统字体，Windows 下自动回退到微软雅黑）。

## 8. 验收标准

1. `cargo test` 全部通过；`cargo build` 产出可执行文件，双击可运行。
2. 添加任务后立即显示创建时间（本地时区格式）。
3. 点击"开始"显示开始时间，且"已耗时"每秒递增。
4. 点击"完成"显示结束时间与总耗时，状态徽章变为"已完成"。
5. 未开始的任务无法直接完成（按钮不出现）。
6. 关闭程序再启动，任务列表与全部时间字段完整恢复。
7. 删除任务后列表与磁盘文件同步更新。
8. 新建项目出现在侧边栏并持久化，重启后仍在；重名 / 空白项目名被拒绝。
9. 任务可归属 / 切换 / 解除项目，卡片下拉显示当前项目，重启后归属不丢。
10. 重命名项目即时生效并持久化；空名 / 重名被拒绝且保持编辑态。
11. 删除项目后其下任务自动解除归属（任务本身保留），筛选与编辑态复位。
12. 侧边栏点击项目可筛选任务；"全部"显示所有任务；旧版数据文件首次启动自动迁移。
13. 点击「«」收起侧边栏，任务区占满窗口；点击「» 展开恢复；重启后默认收起。
14. 通过弹窗创建任务可填可选描述，卡片灰色小字显示（自动换行）；空描述不显示该行；重启后描述保留；旧数据文件加载正常。
15. 点击「详细添加…」弹出居中模态弹窗：半透明遮罩、点击遮罩 / Esc / 取消均可关闭并丢弃输入。
16. 弹窗可设置标题 / 描述 / 所属项目 / 截止时间；打开时聚焦标题输入框；标题为空或时间格式非法时「创建」禁用且红字提示；提交后任务插在最前、字段齐全、重启后不丢。
17. 「快捷时间」下拉（今天 / 明天 / 本周日 23:59）选中后回填截止时间输入框，手动修改仍可覆盖；截止时间逾期未完成的任务卡片上标红。
18. 旧版数据文件（无 `due_at` 字段）加载正常，`due_at` 自动落空。
19. 任务卡片默认只读展示全部属性（含项目名）；「编辑」按钮位于卡片右下角，点击进入可编辑模式，标题 / 描述 / 项目 / 截止时间可修改，
    保存后卡片更新并持久化；空白标题 / 非法时间 / 项目不存在时保存被拒且保持编辑模式；取消丢弃修改；
    时间字段与「开始 / 完成 / 删除」按钮不受影响。
20. 侧边栏「＋ 添加项目」按钮弹出居中模态弹窗：半透明遮罩、点击遮罩 / Esc / 取消均可关闭并丢弃输入；打开时自动聚焦名称输入框；
    与任务 / 归档弹窗互斥（打开一个关闭其余）。
21. 项目弹窗可设置名称 + 可选开始 / 结束时间；名称为空 / 重名 / 时间格式非法 / 开始≥结束时「创建」禁用且红字提示；
    提交后项目带起止时间创建并持久化，重启不丢。
22. 侧边栏项目行对设置了起止时间的项目小字显示（如 `01-01 ~ 01-31`）；旧版数据文件（无起止时间字段）加载正常，字段自动落空。
23. 任务区双列分组：左列=未开始、右列=进行中，标题带计数、空组提示、各自独立滚动；组内按截止时间升序（无截止排后）；
    「开始」后任务自动进入进行中组、「完成」后从双列消失并进入归档弹窗；编辑截止时间后组内位置自动更新。
24. 侧边栏底部「已完成 (N)」按钮打开归档弹窗：全部已完成任务按完成时间降序展示（标题 / 项目 / 完成时间 / 总耗时），可删除。
25. 侧边栏项目「编辑」原位展开表单：名称 / 起止时间可改，保存后持久化重启不丢；重名（排除自身）/ 空白 / 格式非法 / 开始≥结束 被拒并保持编辑态；取消丢弃。
26. 顶部快捷输入行与「详细添加…」按钮移除；「＋ 添加任务」按钮打开任务弹窗（唯一入口），提交后任务进入未开始组；三弹窗互斥、Esc / 遮罩正常关闭。
27. 任务弹窗与卡片编辑模式可设置优先级（无 / 低 / 中 / 高）；卡片头部显示优先级徽章（高红 / 中橙 / 低灰），未设置不显示；重启后保留。
28. 任务两列排序可切换：优先级（高→低、未设置最后）/ 截止日期（升序、无截止最后）/ 综合（优先级优先、同级按截止日期）；切换即时生效。
29. 项目弹窗与内联编辑可设置优先级；侧边栏项目行名称前显示彩色圆点（高红 / 中橙 / 低灰）；重启后保留。
30. 侧边栏项目排序可切换：优先级 / 截止日期（按项目结束时间）/ 综合；「全部」行恒在最前；切换即时生效。
31. 排序偏好（任务 / 项目各自）持久化：切换后重启程序保持上次选择；旧版数据文件（无排序字段 / 无 priority 字段）加载正常，自动取默认「综合」/ 落空。
